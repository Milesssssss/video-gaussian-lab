# Video Gaussian Lab

用真实视频研究单图高斯先验、视频深度与跨视图约束，构建一个可重复观测、可统一优化的静态 3D Gaussian 场景。

**当前状态：方案 v0.1，外加已测试的 Phase 1 执行基础与合成夹具上的深度约束参考链路；尚未下载模型、尚未运行 SHARP 或 Depth Pro 2、尚未产生实测指标。** 正式协议仍是 `execution_enabled=false`。文档中的阈值、预算与架构仍是待开发集验证的研究设计，不是已取得的性能结果。设计日期：2026-11-22。代码状态见 [实现状态](docs/IMPLEMENTATION_STATUS.md)。

## 研究问题

当相机内参 `K` 与米制相机位姿 `T_world_camera` 已知时，Apple SHARP 的单图高斯先验，配合 Depth Pro 2-L 的视频深度，是否能以合理的计算成本，改善共享高斯场景的几何一致性和独立视角质量？

本仓库不预设答案一定是“SHARP + Depth Pro 2-L”。如果直接从深度初始化普通高斯的效果和成本更好，也应当得到明确结论并调整路线。

## 第一阶段只解决什么

- 输入：真实、静态、短距离、有平移视差的视频；可靠的内参与米制位姿；明确的帧划分。
- 输出：每段视频一个共享的静态高斯场景、独立视角评测、几何诊断和完整成本记录。
- 变量：初始化方式、Depth Pro 2-L 的尺度修正、可选的深度残差约束。
- 固定：预训练模型权重、相机位姿、关键帧、评测视角、渲染器、主要优化和容量预算。
- 后续阶段再处理：跨帧特征关联的额外增益、闭环与位姿联调、持久空间特征、新网络训练、长视频与动态场景。

“完整”在 Phase 1 指**合并视频实际观测到的静态表面**。没有观测到的背面不作为测得几何，不承诺完整房间、任意视角或物理正确的遮挡补全。

## 最小实验矩阵

所有组使用各自初始化产生的几何，经过同一规则的可见性筛选与容量控制；不能在 SHARP-only 对照组中暗中使用 DP2 深度。

| 组 | 初始化 | DP2 尺度修正 | 共享 RGB 优化 | DP2 深度损失 | 作用 |
| --- | --- | --- | --- | --- | --- |
| S0 | SHARP | 无 | 无 | 无 | 放入同一坐标系后的诊断起点 |
| S1 | SHARP | 无 | 有 | 无 | 共享优化是否有效 |
| S2 | SHARP | 每关键帧一个标量 | 有 | 无 | 额外尺度信息的增益 |
| S3 | SHARP | 同 S2 | 有 | 有 | 额外深度残差的增益 |
| D0 | DP2 深度反投影普通高斯 | 不适用 | 有 | 无 | 深度初始化的实用基线 |
| D1 | 同 D0 | 不适用 | 有 | 有 | 同样深度正则下比较初始化路线 |

S2/S3 与 D0/D1 比较的是**整套初始化策略的实用价值**，不能由此独立证明 SHARP 某个网络层、特征或第二层高斯的因果作用。所有组的具体定义以实验协议为准。

## 第一阶段怎么推进

1. **P1.0：准入与数据审计。** 固定依赖版本、使用权限、相机与深度契约；先排除坐标和数据泄漏问题。
2. **P1a：两个开发场景。** 先完成 S0/S1/S2/D0 的 8 次基础运行；另计 4 次 S3/D1 检查，最多再增加 8 次有登记的完整开发运行。依据实测资源和有限候选冻结参数。
3. **P1b：四个锁定测试场景。** 冻结后运行 S1/S2/S3/D0/D1，每组 3 个种子，共 60 次正式运行；S0 仅提供无需优化的诊断输出。
4. **P1c：决策报告。** 根据独立视角、几何和成本，决定保留 SHARP、转向深度初始化、先修复相机链路，或停止当前路线。

P1b 不是现在就启动的任务。它依赖 P1a 的实际耗时、显存和稳定性结果；预算无法满足时缩减范围并提前登记，不能在查看测试结果后删组或挑场景。

## 文件与运行边界

- [协议参数](configs/phase1_protocol.json) 是设计登记文件，`execution_enabled=false`。`python -m vglab.cli run-official` 会拒绝正式运行，不是实验启动命令。
- [场景清单示例](examples/scene_manifest.json) 是合成的格式示例，不代表已有视频或采集记录。
- [实验报告模板](experiments/REPORT_TEMPLATE.md) 规定未来需要保存的证据。
- [协议冻结表](experiments/FREEZE_TEMPLATE.md) 列出测试前必须填定的参数、候选选择和失败规则。
- 原始视频、用户采集、权重、缓存、生成场景和渲染不进入 Git；仓库只保存清单、参数、结果摘要与可追溯引用。
- 本仓库没有复制第三方模型代码或权重，也没有为上游材料重新授予许可。Apple 模型的许可限制是实际执行前置条件，见[许可记录](docs/THIRD_PARTY.md)。仓库设为 private 不能改变这些限制。
