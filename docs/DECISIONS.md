# 设计决策记录

所有决策状态均指方案层面。日期：2026-11-22。

| ID | 决策 | 理由 | 重新审议条件 |
| --- | --- | --- | --- |
| ADR-001 | 先做已知 K/T 的静态短视频 | 隔离相机与动态误差，降低归因难度 | 固定位姿链路可信且出现可测的相机瓶颈 |
| ADR-002 | 使用一个共享 Gaussian 参数集 | 逐帧完整场景累积不等于观测融合 | 后续需要子图，但子图间仍需明确定义共享关系 |
| ADR-003 | SHARP/DP2 权重冻结 | 先评估现有先验的价值 | P1 证明值得保留且训练目标/数据/许可明确 |
| ADR-004 | DP2 优先作为尺度与深度残差来源 | 外部逐像素注入可能破坏已训练高斯构造 | 出现足够局部误差证据后，单独增加注入消融 |
| ADR-005 | 主实验保留 S0/S1/S2/S3/D0/D1 | 分开共享优化、尺度信息、深度正则与初始化路线 | 开发资源不足时在测试前正式缩减并登记未回答问题 |
| ADR-006 | P1 不训练“全局特征约束” | 语义相似不等于同一表面，新增变量会混淆基本收益 | P2 有明确对应关系、可见性与损失定义 |
| ADR-007 | 先 split，再运行网络 | 联合视频深度的上下文可泄漏留出图像 | 不放松；如采用 transductive 设置必须另列任务 |
| ADR-008 | 几何评测使用独立参考 | 对 DP2 的贴合度只说明正则执行了 | 无参考时只给相对一致性结论 |
| ADR-009 | 记录冷/热成本，不只报优化时间 | SHARP+DP2 双推理是路线实际代价 | 只有部署场景明确存在合法可复用缓存时才给独立热路径结论 |
| ADR-010 | 数据/权重/结果大文件留在 Git 之外 | 保留可复现清单而不传播用户采集或第三方权重 | 经授权后可发布许可允许的派生材料，并单独记账 |
| ADR-011 | 先准备 private 仓库 | 尚在方案阶段，没有公开发布要求 | 用户明确选择公开后再处理公开范围 |
| ADR-012 | 本轮交付文档，不伪装成实现 | 用户要求先严谨方案，缺少实际数据与执行条件 | 下一轮按第一阶段任务推进实现 |
| ADR-013 | P1 是离线 batch，不宣称在线回访无遗忘 | 联合深度窗口与跨 source 准入可能使用后续帧 | P2 分别对各时间前缀运行完整管线、另列成本后再评价 |
| ADR-014 | 主要配对要求所有预定场景与种子完整 | 防止 OOM 或失败场景退出分母后形成幸存者偏差 | 修改设计需在测试前重新登记，不以事后删样本修补 |
| ADR-015 | 深度约束先接一条开发用参考链路（EWA 参考渲染 + 光学轴相对步 + 固定 teacher），正式渲染器与训练器另立 | 先验证 DP2→teacher→渲染深度→残差的坐标、掩码与梯度边界，避免把接线错误误判为方法无效 | 官方渲染器完成单帧对齐验证后，用正式优化器替换；参考链路只保留为回归测试 |
| ADR-016 | 模型适配器采用注入式后端契约 + 权重/许可/加速器前置门；加速器探测覆盖 CUDA 与 MPS | 允许在无权重环境下测试转换与隔离，同时不在 macOS/MPS 上误报“无 GPU”，又不会把未发生的推理记为已运行 | 真实 torch 桥接入后，把后端实现固定到协议记录的 commit 与权重哈希 |

## 协议修订条目格式

每次实质性修订增加：日期、旧版本、新版本、变化、触发证据、已看过哪些开发/测试结果、哪些结论需要重跑。对 source/test 划分、主指标和阈值的变动尤其如此。
