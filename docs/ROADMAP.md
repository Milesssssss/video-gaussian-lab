# 分阶段路线

状态：设计 v0.1 · 2026-11-22。阶段按照证据推进，不按预设日历自动切换。

## 总体路线

| 阶段 | 主要问题 | 最小产出 | 进入下一阶段的依据 |
| --- | --- | --- | --- |
| **P1：已知相机的静态短视频** | SHARP 先验与视频深度是否有可复现的组合价值？ | 一套可复现基线、独立视角评测、几何诊断、成本曲线、路线决策 | 数据/实现可信，初始化与优化效应可区分，明确是否保留 SHARP |
| P2：跨视图关联与共享场景更新 | 固定相机下，显式关联是否减少重复表面、提高重访稳定性？ | 固定特征/轨迹与几何验证、关联/新建策略、闭环观测图，对照消融 | 在 P1 最佳可用初始化上取得独立增益，容量控制不会掩盖旧区域退化 |
| P3：长序列与相机不确定性 | 如何管理子图、漂移、内存与回访？ | 子图/关键帧策略、保守位姿联调、长序列容量与旧视图保持评测 | 质量随时长可控，误差可诊断，资源满足明确目标 |
| P4：可部署路线 | 研究收益能否保留到目标平台和业务输入？ | 使用条件明确的模型选择、部署性能、采集和导出流程 | 独立业务验收，不以研究集结果替代产品验收 |

学习式全局特征或 persistent tokens 是 P2/P3 的候选研究分支，不是已经选定的技术。先验证几何和观测关联能否解决问题，再决定是否训练新模型。

## P1 内部里程碑

### P1.0 — 能相信输入与比较

交付：可追溯的视频与相机清单、帧级 source/validation/test 划分、坐标与深度小样例、依赖/权重版本登记、使用条件记录。

完成条件：训练和评测数据路径分离；相机方向、米制尺度、内参图像分辨率、深度 Z/range 无歧义；相机质量可以量化。无法满足时只开展格式与几何校验，不运行模型质量比较。

### P1a — 两个开发场景验证链路

交付：S0/S1/S2/D0 的 8 次基础运行；S3/D1 的 4 次必要深度检查；最多另加 8 次完整开发运行，用于已登记的有限候选选择。至少一个有边界与遮挡、一个有平面与重访的短场景。故障重跑与全部成本另记。

完成条件：独立渲染通路、损失梯度和有限值正确；对照组信息隔离；基础几何诊断通过；实测冷/热耗时和显存；以开发集固定容量、分辨率、损失权重与预算。没有证据时不得写“收敛”“融合成功”。

### P1b — 锁定评测

交付：四个此前未用于选参的场景、正式运行登记、逐场景结果与失败案例。

完成条件：所有有效实验使用同一冻结协议；场景失败和 OOM 计入汇总；报告 3 个种子方差，场景作为比较单位。不能用一个场景中的上百帧冒充上百个独立样本。

### P1c — 做路线决策

交付：[实验报告](../experiments/REPORT_TEMPLATE.md)、可复核的输入/配置/结果摘要和以下结论之一：

- **保留 SHARP。** 在实际质量—成本权衡上优于深度初始化，且没有掩盖几何退化。
- **保留深度，简化初始化。** D0/D1 更好或收益接近但成本明显更低，后续关联研究基于它展开。
- **先修正输入。** 相机、同步或曝光误差主导，当前模型比较不足以归因。
- **当前证据不足或路线不成立。** 停止扩大范围，记录失败与剩余问题。

达到负结果也可以完成 P1。进入下一阶段的理由应当来自已观察到的剩余误差，而不是“把更多模型接上试试”。

## 本阶段主动延后

| 延后的事项 | 原因 | 重新开启的条件 |
| --- | --- | --- |
| 训练全局场景 token / 多帧 SHARP | 与基础几何和融合变量同时变化，会失去归因 | P1 显示初始化有价值且关联误差仍是主要瓶颈 |
| 联合优化相机位姿和尺度 | 可通过相机自由度吸收错误深度，掩盖模型问题 | 固定位姿失败能被独立相机证据解释 |
| 动态物体与 4DGS | 静态表面身份和时间形变不是同一任务 | 静态链路通过且有独立动态业务目标 |
| 长视频/大仓库实时建图 | 当前无法从小场景推断内存、漂移与速度 | P1/P2 的资源曲线支持扩展 |
| 交互界面、引擎接入与产品发布 | 不影响第一阶段科学问题 | 有可复核结果、输出契约和可用许可路线 |

## 阶段变更规则

变更研究目标、正式测试场景、主指标、对照组或判定门槛，必须先更新协议版本与决策记录。已经观察过的测试集变为开发证据；不能修改阈值后继续称同一次预注册测试。
