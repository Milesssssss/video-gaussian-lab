# 第一阶段实验协议：SHARP 初始化与视频深度对共享高斯场景的价值

**状态：方案阶段，尚未执行实验。** 本文件定义一次小规模、可归因、可接受阴性结果的研究。所有数值均为拟预注册的探索设置，不代表理论保证、产品精度承诺或已取得的结果。

## 1. 研究问题与允许得出的结论

输入是同一真实静态场景的短视频、与图像严格对应的标定内参，以及固定的米制相机轨迹。问题是：

> 在固定数据、共享场景优化器和高斯预算下，SHARP 提供的初始化，结合 Depth Pro 2 L 的深度，是否比普通深度反投影初始化更有效？

把问题拆成四个可反驳假设：

| 假设 | 主要对照 | 可回答的问题 |
|---|---|---|
| H1 | S1 对 S0 | 共享多视图 RGB 优化能否修复独立单帧高斯的主要不一致？S0 只作诊断。 |
| H2 | S2 对 S1 | 每个关键帧的单标量尺度校准是否有增益？ |
| H3 | S3 对 S2，以及 D1 对 D0 | 优化阶段的深度残差是否有独立增益？ |
| H4 | S2 对 D0，以及 S3 对 D1 | 初始化策略的实际价值：SHARP 方案相对于直接深度反投影，是否提供值得额外成本的质量收益？ |

H4 是完整初始化策略的实用比较，不是 SHARP 特征的净因果效应。两类策略虽使用同一 DP2 版本与 source 图像，但深度的使用方式和信息量、层数、外观、协方差均不同。它们的差值不能被单独归因于“学习特征”“第二层”或某个高斯属性。

本阶段不验证无限长视频、动态对象、完整仓库、手机实时运行或端到端前馈免优化。这里的“共享场景”是一个世界坐标系内、由多个真实源视角共同优化、能从留出相机渲染的高斯集合；不是逐帧 PLY 文件的简单并集。未被观测的背面不能被计作已重建的真实几何。

## 2. 前置条件与停止条件

### 2.1 数据、模型与许可

实验开始前必须登记：视频所有权或使用许可、数据集条款、模型代码和权重各自的许可、模型版本与权重哈希。记录使用目的与许可是否兼容，不能仅凭“开源”认定可用。

Depth Pro 2 的公开权重许可明确限定为非商业研究，并排除产品开发及商业产品或服务；SHARP 也须分别核对代码与模型许可。若研究目的不在许可范围，先取得适用授权，或把替代模型作为新的、有明确命名的实验方案。不能静默替换模型后仍报告“Depth Pro 2 L”。见 [Depth Pro 2 LICENSE_MODEL](https://github.com/apple-aiml-research/ml-depth-pro-2/blob/main/LICENSE_MODEL) 与 [SHARP 官方仓库](https://github.com/apple/ml-sharp)。

采用真实拍摄的静态视频。生成视频不能作为本阶段的几何证据。剔除或单独标注移动物体、镜面、透明物体、严重曝光跳变及滚动快门变形；标注规则在 dev 冻结，不能根据某个方法在 test 上的误差重新画 mask。

### 2.2 相机数据不是无误差真值

米制轨迹也可能有漂移、时延和外参误差。须记录坐标约定、单位、图像与位姿时间戳、去畸变、裁剪与缩放后的 K、轨迹来源，以及已知的不确定度。K 和位姿在所有实验组中保持相同，不进行联合相机优化。

提供 `pose_provider.used_eval_rgb: true | false | unknown`。若录制时的 ARKit 或全视频 SfM 已使用留出 RGB 估计轨迹，结果只能称为“给定该固定轨迹的渲染留出评测”。严格未见图像的几何泛化评测需要独立参考轨迹，或可复现的 source-only 轨迹方案。`true` 或 `unknown` 不能被省略，也不能包装成完全未见视图的几何测试。

### 2.3 未满足以下条件，不启动 test

- 场景和视图划分、模型版本、输入预处理与许可登记完成。
- 单位、相机轴向、外参方向、深度定义和协方差变换通过可复现检查。
- 优化器、准入规则、高斯预算、损失权重及停止步数在 dev 冻结。
- 根据 dev 实测填写硬件、单次时间上限、总 GPU 小时和峰值显存上限；不预先声称“几小时可以完成”。
- test 数据尚未被用于调参，留出帧的访问边界可审计。

许可不适用、关键标定缺失、无法排除泄漏、预算未冻结或实现未完成，均记为 **blocked**，不是算法失败，也不是已完成效果验证。

## 3. 数据规模、场景划分与留出规则

### 3.1 固定 2 个 dev 场景和 4 个 test 场景

建议覆盖两类尺度：桌面或局部对象，以及房间或工业局部区域。test 场景在拍摄地点和对象组合上与 dev 分离；不得从同一段视频裁出“不同场景”充数。

| 场景角色 | 建议内容 | 用途 |
|---|---|---|
| dev-01 | 纹理清楚的桌面，含细杆或椅腿 | 接口、颜色、尺度和优化稳定性 |
| dev-02 | 房间局部，含平面、遮挡和回访 | 内存、准入、深度残差及资源冻结 |
| test-01 | 未见过的细结构与对象边界 | 局部细节是否保留 |
| test-02 | 弱纹理墙面与多深度层 | 平面重影、厚度和几何偏差 |
| test-03 | 重复结构，例如货架或托盘 | 匹配歧义和重复表面 |
| test-04 | 有平移基线的绕行与回访 | 已有区域能否被稳定更新 |

这些是场景选择条件，不是必须购买的设备或必须存在的素材。最终场景 ID 与内容在实验清单中登记。当前只计划 4 个 test 场景；如要扩展到 6 个，须在查看这 4 个 test 结果前冻结扩展规则和预算，否则作为下一轮独立研究。

### 3.2 每场景预算与视图划分

- source 关键帧硬上限：**48 帧**。dev 决定统一的最大数量与选帧规则，test 不按方法改变。
- 留出目标：**24 帧，分成三个连续时间块，每块 8 帧**，覆盖早、中、晚或回访阶段；不是随机每隔若干帧留一张。
- dev 场景：留出帧标记为 `validation`，用于有限的方案冻结。
- test 场景：留出帧标记为 `test`，只用于最终评测；其 `validation` 可为空。
- canonical 图像长边固定为 **1280**，保持纵横比并同步变换 K。SHARP 内部网络需要的采样属于模型适配，须记录。DP2 和评测图像的精确网格在 dev 冻结。
- 候选防泄漏间隔为留出块边界外至少 **0.2 秒且至少两帧 source 候选间隔**；这只是近重复抑制规则，不保证独立视角。

报告每个留出块与最近 source 的时间差、相机平移距离、旋转角、共视比例和近似视差分布。纯旋转、基线过小和回访重合度不足应被记录；视频帧连续性本身不证明三维可观测性。

### 3.3 先划分，再运行任何模型

`source`、`validation`、`test` 是互斥的 view split；dev/test 是另一个层级的 scene split。

留出 RGB 不得进入：SHARP、DP2 上下文窗口、光流或特征匹配、三角化、尺度拟合、准入、mask 自动调优、颜色校正、优化损失或任何场景状态更新。DP2 的候选 source 窗口为 **16 帧、重叠 4 帧**；只在 source 序列内构建。重叠帧的多次深度预测按逐像素固定 log-median 合并，规则在 dev 冻结。

留出帧仅在隔离的评测环节读取。dev validation 可反馈到预注册的有限调整；test 结果不得反馈到本轮模型、配置或 checkpoint 选择。需要修改时，新建协议版本，并把已查看的 test 结果标记为探索结果。

## 4. 实验组定义

所有实验组使用冻结模型、固定 K 和米制位姿、相同 source ID、同一高斯预算档和同一渲染器。优化后的产物始终为一个共享场景。

| ID | 初始化 | 尺度处理 | 优化目标 | 角色 |
|---|---|---|---|---|
| S0 | SHARP 逐帧预测，经共同坐标转换、确定性准入和预算控制 | 保留 SHARP 原米制预测 | 无 | 仅诊断独立预测的原始冲突，不作为优化方法的公平质量基线 |
| S1 | 与 S0 相同 | 与 S0 相同 | 共享多视图 RGB | SHARP-only 主基线 |
| S2 | 与 S1 相同 | 每个关键帧用 DP2 做整幅图单一标量校准 | 与 S1 相同 | 检验深度尺度初始化 |
| S3 | 与 S2 相同 | 与 S2 相同 | 同 RGB ＋ DP2 可见表面深度残差 | 检验优化阶段深度约束 |
| D0 | DP2 深度反投影形成普通高斯，颜色来自 source RGB | DP2 的米制深度 | 与 S1 相同 | 比较两种初始化策略的实际质量与成本 |
| D1 | 与 D0 相同 | 与 D0 相同 | 与 S3 相同 | 在相同深度损失下比较两种初始化策略的实际价值 |

S1 不得在选帧、准入、几何过滤、置信度或优化中间接使用 DP2。否则 S1 已被深度信息污染，S1→S2 的归因不成立。

### 4.1 单标量尺度初始化

“全局尺度”在本协议中严格指 **每个源关键帧的整幅图共享一个标量 `s_i`**，不是逐像素校正，也不是给整个序列只拟合一个数。

在固定的有效静态内部区域，比较 SHARP 层 0 高斯单独渲染的可见表面深度 `Z_sharp` 与 DP2 的相机 Z 深度；排除渲染 alpha 不足的像素，避免把两层或背景混合成尺度参考：

```text
log(s_i) = median(log(Z_dp2) - log(Z_sharp))
mu_camera' = s_i * mu_camera
Sigma_camera' = s_i^2 * Sigma_camera
```

随后再用固定相机位姿转换到世界坐标。不得缩放相机平移，不得只改高斯中心而遗漏尺度或协方差。稳健估计器、有效深度范围、边缘排除宽度和最少支持像素数在 dev 冻结。

报告每帧 `s_i`、支持比例及拟合残差。极端尺度或支持不足触发明确诊断，不能静默剪裁成好看的值，也不能在查看 test 质量后删除失败场景。

### 4.2 DP2 深度残差

S3 与 D1 使用相同的归一化稳健 log-depth 残差：

```text
L_depth = sum_p w_p * rho(log(Z_render(p) + eps) - log(Z_dp2(p) + eps)) / sum_p w_p
L_total = L_rgb + lambda_depth * L_depth
```

这里约束的是 source 相机下的 **可见表面渲染深度**，不是要求所有 SHARP 层或所有高斯中心等于单张深度图。候选实现使用累积不透明度归一化的 expected depth，并排除低覆盖、明显多表面混合、动态、透明、镜面及深度跳变边界；其具体规则要在 dev 检查并冻结。

权重 `w_p` 来自固定有效性规则及 source-only 几何一致性。DP2 没有提供原生像素置信度时，不能把自制权重标记为模型校准置信度。`lambda_depth` 只允许在 dev 做有限合法性与梯度量级检查，不在 test 上搜索。深度损失降低仅说明更接近该先验，不证明更接近真实几何。

优化开始前，仅由 teacher/source 观测确定固定的 `teacher_fixed_mask` 和基础可靠性权重 `q_p`，不能根据当前高斯误差不断缩小这份基准区域。另设依赖渲染 alpha 的 `renderer_mask`，并对其 eligibility 选择 detach；实际权重为 `w_p = teacher_fixed_mask(p) * q_p * renderer_mask(p)`。二者必须分别保存或记录统计，不能合并成无法追踪的动态 mask。

逐帧记录 teacher 无效深度、动态区、边界、几何不一致、渲染 alpha 不足等像素排除原因，固定 teacher 有效像素数、实际监督像素数、`depth_supervision_coverage`（实际有效像素数 / 固定 teacher 有效像素数）、alpha 分布，以及覆盖低于门槛的持续步数。固定 teacher 集合为空时覆盖记为 NA，不能伪造 100% 覆盖。detach 不能消除跨优化步骤通过降低 alpha 逃避监督的问题，因此最小覆盖率、允许持续步数和停止规则都在 dev 冻结。具体梯度与失效边界见 [TECHNICAL_DESIGN.md §10.3](TECHNICAL_DESIGN.md#103-s3与d1独有的depth-loss)。

单个 source 样本没有有效监督时，标记 `skipped_empty_depth_mask` 并记录原因，不把它报告成深度误差为零。整批监督为空、损失非有限，或监督覆盖持续低于冻结门槛时，停止并按缺失/失败规则记为不可评估。不能靠分母加 epsilon 生成零 loss 后继续宣称深度约束有效。S3 与 D1 必须同时报告监督覆盖及失败情况，不能只展示残差下降。

### 4.3 普通高斯基线必须足够合理

D0/D1 不能故意采用明显不适合渲染的微小点或不透明度设置。建议采用确定性相机像素足迹初始化尺度，颜色为同一 source RGB，旋转由固定规则的局部法向或相机朝向给出；规则、法向邻域及边界处理均公开。

统一使用 **degree 0 的颜色表示**。初始 footprint 和 opacity 可在 dev 内独立确定合理默认值，但调节预算须记账；之后全 test 使用同一配置。记录这些属性的分布，避免“SHARP 胜出”只是普通基线初始化错误。

## 5. 公共融合、准入与优化控制

### 5.1 “相同融合”指相同算子和门限，不是相同预测结果

各组使用相同准入规则，但几何来自各自初始化。准入只使用 source RGB、K、固定轨迹、各组自身的渲染深度和可见性；不能把 DP2 生成的深度或遮挡图偷偷用于 S1 的公共模块。source-only feature tracks 仅用于离线诊断，不进入本阶段的准入决策或损失。

第一阶段只使用确定性操作：共同坐标转换、可见性检查、重复候选抑制、固定预算采样。使用各组自身的投影、渲染深度与可见性，按预先定义的几何规则处理重复候选；无法确认对应时保留为未关联候选，并由预算规则控制。接近的中心不自动代表同一表面，禁止无条件平均不同遮挡层的高斯。

准入变化本身可能是尺度初始化的中介效应。S1→S2 除最终指标外，还应报告候选保留率、关联变化和来源分布；若变化主导结论，可在 dev 做一次固定候选 ID 的诊断对照，不能把它隐含为纯尺度变换的证明。

### 5.2 高斯预算与优化预算

拟采用一个统一预算档 `B`；在 dev 根据实际资源从 **{250,000，500,000，1,000,000}** 中选择一档并冻结，不按 test 场景或实验组选择最有利档位。初始候选不足 `B` 时记录实际数量，不通过复制或零贡献高斯凑数。

主矩阵在优化阶段关闭增密和结构性裁剪，固定参与优化的参数集合与高斯上限。记录总数量和有效数量，例如 `opacity > 0.01` 的数量；有效数量阈值只作诊断。

所有优化组使用相同 RGB 损失、学习率日程、batch 规则、source 采样序列、优化步数与可训练参数类别。不同初始化的数值条件可能不同，故同时报告收敛曲线。相同高斯数量不自动等于相同表达能力，相同步数也不等于相同计算成本。

主矩阵冻结场景曝光处理与色彩空间，禁止各组通过额外的颜色拟合补偿输入差异。需要曝光模型时必须作为所有组一致的预注册处理。

### 5.3 本阶段明确推迟

学习全局 scene tokens、跨帧特征适配网络、SHARP 微调、可学习融合器、联合 pose 优化、动态场景、对象语义、长期回环及手机部署均不进入本阶段。feature tracks 仅用于 source-only 诊断；各组自身的渲染深度与可见性可用于确定性准入。不能把这些机制捆绑加入 S3 后，将全部增益归因于深度。

## 6. 分阶段执行与硬预算

### P1a：dev 管线与资源冻结

基础运行：**2 个 dev 场景 × S0/S1/S2/D0＝8 次**。使用一个固定 seed，仅检查输入正确性、共享优化是否工作、尺度初始化及普通基线是否合理，同时获得真实运行成本。

在进入 test 前，允许最多 **4 次必要的附加诊断运行：2 个 dev 场景 × S3/D1**，用于深度损失的梯度、有效像素与资源合法性检查。它们单独记账，不计入“8 次基础运行”，不用于大规模超参数搜索。其他故障重跑也须保留失败记录、原因和成本；超过该范围需重新登记预算。

这 8＋4 次基准运行不保证足以冻结高斯预算、D0/D1 初始化、深度权重和优化步数。因此另设 **最多 8 次新增的完整 dev 优化运行**：每次候选变更必须在两个 dev 场景上配对运行，共 2 次，最多 4 个候选变更。检查和调整按 **资源/高斯预算 → D 臂 footprint 与 opacity → 深度权重 → 优化步数** 的顺序进行；每项可不调整，但不能为每个 arm 另开不记账搜索。调参使用的参照 arm、候选值和选择目的必须在执行该候选前登记，不能跑完后更换目标。

| 调整项 | 候选和选择依据必须记录的内容 | 主要限制 |
|---|---|---|
| 资源与 `B` | 离散候选档、参照 arm、峰值显存、完整耗时、有效数量及覆盖 | 所有正式组最后使用同一档；资源上限优先，不按 test 质量选 |
| D 臂初始化 | 两套明确的 footprint/opacity 配置及其来源，dev RGB、覆盖、数值稳定性 | 最终 D0/D1 同配置；不得只保留漂亮截图或单独无限调节 |
| `lambda_depth` | 候选权重、梯度量级、固定 teacher mask 覆盖及渲染/参考指标 | 不以 DP2 自身残差降低作为唯一选择目的 |
| 优化步数 | 候选步数、完整时间与 dev 收敛曲线 | 最终所有优化组同一步数，不按组挑终点 |

因此 P1a **最多 20 次计划运行**，即 8 次基础＋4 次深度诊断＋8 次调参；其中 S0 的 2 次是无优化诊断，其余最多 18 次是优化运行。故障尝试和获准的重试另记实际成本。预算内无法合理冻结时，P1a 记为 inconclusive 或登记新的研究轮次，不能先打开 test 再补调参。

P1a 结束必须产出冻结的配置哈希、数据划分哈希、seed 列表、每组资源估计和总预算。不能仅依据 dev 的正向效果决定保留哪些 test 场景。

### P1b：冻结 test 对照

完整主矩阵为 **4 个 test 场景 × S1/S2/S3/D0/D1 × 3 个 seeds＝60 次优化运行**。三个 seeds 固定为 `17, 29, 43`；同一 seed 在各组采用相同 source batch 顺序。

S0 在 test 如导出，只计为不优化的诊断产物，另报成本，不纳入 60 次优化运行。冻结模型的确定性预测允许跨 seeds 复用缓存，但必须按第 8 节披露成本。

若 P1a 证明资源不足以执行完整矩阵，必须在打开 test 结果前选择缩减方案：例如先执行 S1/S2/D0，明确 H3 及 S3/D1 对照未验证。不能做半组对照后把缺失组当作无收益。

`run_wall_time_cap_s`、`total_gpu_hours_cap`、`gpu_memory_cap_gb` 必须根据 P1a 实测填入运行清单。超时、OOM、数值异常与无输出都作为失败计数；不能自动用降低分辨率或减少帧数的结果替换失败组。

### 缺失、失败与重试规则

正式的 P1b 配对结论要求该假设所需实验组的 **4 个场景 × 3 个 seeds 全部完成**。任一必要 arm/seed 缺失、算法导致 OOM/NaN、超时或没有可评测产物，该假设总体结论为 **inconclusive**；相应表格填 NA 并注明原因，不能按幸存场景重新计算“3/4 通过率”，也不能替换成最好 seed。已完成子集可以完整披露，但必须标为探索性，不能代表原计划总体。

H2 只受其所需 S1/S2 的完整性约束；其他非必要实验组失败不抹去一个已经完整的独立对照。H3 的整体结论须同时具备 S3/S2 和 D1/D0；H4 的整体结论须具备 S2/D0 和 S3/D1。某个子对照完成、其他子对照缺失时，只能报告该子对照，不能声称整体假设通过。

仅对有日志证实的基础设施故障，例如机器中断或存储不可用，允许 **一次完全相同配置、同 seed 的重试**；算法 OOM 或数值异常不自动归为基础设施故障。全部失败尝试、重试原因与时间/显存成本保留，不从资源报告中删去。配置变更属于新的 dev 候选或新的研究版本，不能作为同一次 test 的隐形重试。

## 7. 指标与统计单位

### 7.1 留出渲染质量

在相同 canonical 网格、固定相机和同一有效静态 mask 上评测。禁止用 test RGB 对齐亮度、颜色、姿态或深度。

- **PSNR**：RGB 归一化到 `[0,1]`，按预注册的 sRGB 空间计算 `-10 log10(MSE)`。颜色空间不得在组间变化。
- **SSIM**：固定实现、窗口与版本，记录参数。
- **LPIPS**：固定网络与版本，例如 AlexNet v0.1，按实现要求映射到 `[-1,1]`。作为主要感知指标，但不能代表几何正确性。
- **覆盖率**：记录评测像素累积 opacity 达到冻结阈值的比例；主 RGB 指标在共同有效 mask 的所有像素上计算，不只挑各组覆盖成功的像素。

先对每个留出时间块求均值，再对三个块等权平均，得到每个 seed 的场景值；再平均同场景的三个 seeds。**统计单位是 4 个独立 test 场景，不是 96 帧，也不是 12 个独立场景。** 报告逐场景配对差值、场景均值、中位数、最差场景和 seed 波动。小样本 bootstrap 如展示，只作描述，不能作为泛化可靠性的强证据。

### 7.2 独立几何验证

DP2 不能充当几何 GT。优先使用独立标定扫描、结构光、激光或具有误差说明的实测尺寸。参考数据不得进入初始化、准入、深度锚定或 test 调参。

对场景使用一个预先标定的世界坐标变换；主结果禁止为每个方法单独做 Sim(3) 拟合来消除尺度错误。若额外报告刚体或相似变换后的分数，须明确其诊断含义，并同时保留原尺度结果。

几何比较应从固定评测相机渲染的可见表面深度反投影，使用共同采样规则与参考可见区域；不把高斯中心直接当作真实表面采样。

- **绝对深度误差**：独立参考的有效可见像素上，报告 MAE、中位数和 P90，单位米。
- **表面 F-score**：对预测表面与参考表面分别计算距离阈值内比例 `P_tau`、`R_tau`，`F_tau = 2 P_tau R_tau / (P_tau + R_tau)`。候选主阈值为 **3 cm**，仅在参考综合不确定度不超过约 **1 cm** 时解释；**1 cm** 档只在参考不确定度约 **3 mm** 或更好时作为附加结果。
- **平面厚度**：在预先标注的不透明静态平面 ROI 内，计算到参考平面的有符号距离 P90−P10，同时单独报告偏移中位数，区分“厚”和“整体位置错”。
- **实测尺寸误差**：固定若干独立测量距离，报告绝对误差和相对误差；不使用它们反向校准 test 场景。

没有足够独立参考时，本阶段可以完成渲染与一致性评测，但必须把“真实几何正确性”标为未验证。

### 7.3 跨视图与回访诊断

固定 source tracks 与几何门限，报告重投影误差、有效多视图支持率、深度一致性残差及关联失败率。这些是自洽性诊断，可能共同犯错，不能替代独立 GT。

第一阶段是离线 batch 重建：DP2 可以使用全部 source 构成的合法窗口，准入可以检查其他 source，初始化完成后再对同一个固定高斯集合优化。因此，优化早期和后期的 checkpoint **不是**时间因果的“回访前”与“回访后”场景状态。对有回访的场景，仅做以下诊断：

- 对同一个最终共享场景，分别在早期与回访时间块的留出相机上报告 LPIPS、覆盖率，以及具备参考时的平面厚度。结果表示该场景能否同时解释两段观测，不表示在线更新没有遗忘。
- 按 source 时间顺序记录准入候选的冗余率、保留来源比例和预算排除或代表替换情况。排序日志仍可能利用后续 source 的 DP2 上下文和几何支持，必须标明 **batch lookahead**；它只能诊断最终冗余及资源分配，不是在线更新或因果回访证据。固定预算下不能只用高斯总数判断是否去重。
- 在预标注的单一不透明平面 ROI 内，沿评测射线按高斯贡献权重聚类深度。若出现至少两个相隔超过 **3 cm**、且各占该射线贡献至少 **10%** 的深度簇，记为一次双层表面诊断，报告其像素比例。门限需在 dev 冻结；真实多层、透明区域不参与。该指标是探索性重影诊断，不是精确表面数量真值。

真正的因果回访试验推迟到 P2。未来若比较回访前后的状态，必须对每个时间前缀分别仅用该前缀内的 source 重算 DP2 上下文、对应/准入和优化，禁止复用含未来帧的深度或关联缓存；独立列出运行与成本，不塞入本阶段 60 次主矩阵。

## 8. 时间、内存、缓存与公平比较

每次运行分别记录图像解码与相机预处理、位姿求解或整理、模型加载、SHARP 推理、DP2 推理、尺度拟合、准入、共享优化、导出的耗时。相机轨迹若作为已有输入，不虚构求解耗时；但须明确实际部署仍需该轨迹来源。

至少区分三种成本：

| 成本口径 | 包含内容 | 用途 |
|---|---|---|
| cold reconstruction | 从磁盘加载权重、所有必需预处理与推理、优化、导出 | 首次构建场景的成本 |
| warm reconstruction | 模型已驻留，但重新执行本场景的预处理与推理 | 连续服务吞吐 |
| cached replay | 复用已计算的深度或初始化，仅执行后续处理 | 研究重复运行成本，不能冒充端到端速度 |

首次下载权重等环境准备单列。缓存跨 seeds 复用时，记录真实执行成本，并给出加回该组必需初始化成本的端到端核算；核算值与实测值分列，不声称每次都重新执行过。

主矩阵报告固定步数结果。利用带时间戳的中间 checkpoint，另给一个 **P1a 冻结的等端到端时间预算** 对照；计时起点包含该组必需的模型与相机预处理。只取截止时刻已完成的 checkpoint，不取未来最优结果。如果初始化尚未完成，应报告“预算内无可用产物”。缓存与非缓存口径分开，不能用 A 组全流程时间对比 B 组缓存后优化时间。

checkpoint 保存间隔须在 dev 冻结并尽量使用同一时间调度。离散 checkpoint 的比较必须记录其实际完成时间 `t_checkpoint`、预算 `T`、`budget_utilization = t_checkpoint / T` 与剩余时间 `T - t_checkpoint`；时间包含使该产物可读取的保存或导出成本。若两组最近 checkpoint 距截止时刻的距离不同，应同时展示这些值，不能将较早产物误称为充分使用了相同预算。不得利用未来 checkpoint 插值或在 test 上选择更有利的保存频率。

记录峰值 GPU 已分配显存、进程或驱动可见占用口径、CPU RSS、临时数据与最终产物大小。参数文件大小不能用作显存需求。多模型是否同时驻留和硬件型号须固定并披露。

## 9. 预注册的探索性决策规则

以下阈值是小样本研究的工程筛选条件，用于限制事后挑选指标；不是统计显著性边界、行业标准或产品 SLA。若 dev 噪声显示阈值不合适，只能在 test 解盲前修订并登记原因。

**G0：几何门槛可评测性。** 在 test 解盲前登记每个场景的独立几何参考、可见区域、参考不确定度及可计算的指标。以下“至少 3/4 场景”的几何门槛只在 4 个 test 场景都具备相应合格参考时启用。缺少独立参考或参考精度不足时，该几何门槛记为 **NA / 未评测**，不能以 DP2 残差代替、记零分或默认通过；有参考的子集仍可逐场景描述。G0 不满足不妨碍完成第一阶段的渲染、资源和初始化策略比较，但不能宣布几何成功，也不能据此通过面向几何可靠性的下一阶段门槛。

**G1：覆盖与分组非退化。** 所有质量推进条件均同时检查共同有效 ROI 的覆盖：相对于对应基线，场景平均覆盖率下降不超过 **2 个百分点**，早期和回访留出分组也分别检查同一候选门槛。逐场景与分组的 PSNR、LPIPS、覆盖和失败情况必须显示，不能用整体均值掩盖某段视角的系统性塌陷。覆盖门槛失败时，记录质量/覆盖权衡，不能直接宣称无退化成功。2 个百分点同样只是待 dev 冻结的探索阈值；它不取代 G0 或缺失运行规则。

| 决策 | 候选推进条件 | 未满足时的处理 |
|---|---|---|
| 深度尺度初始化值得继续 | S2 对 S1：至少 3/4 场景 LPIPS 改善，场景平均绝对改善 ≥0.01；平均 PSNR 不下降超过 0.3 dB；满足 G1，G0 满足时 F_3cm 不下降超过 0.02 | 若提升小于 seed 波动或不稳定，记录无明确增益，不强行加入主流程 |
| 深度损失值得继续 | S3 对 S2，并检查 D1 对 D0：G0 满足时至少 3/4 场景几何方向改善，平均 F_3cm 增加 ≥0.03，且 LPIPS 恶化不超过 0.01，并满足 G1 | G0 为 NA 时最多声称渲染或自洽性改善；不能声称几何更真 |
| 初始化策略具有实际价值 | S2 对 D0、S3 对 D1：至少一项对照显示稳定感知增益，场景平均 LPIPS 绝对改善 ≥0.01；满足 G1，G0 满足时几何无超过上述门限的退化，等时间曲线支持其成本 | 普通深度高斯相当或更好时，明确 SHARP 初始化策略的额外复杂度尚未获得支持；G0 为 NA 时结论限于渲染与成本 |
| 值得进入第二阶段 | 至少一个核心假设获得跨场景支持，失败模式可解释，成本与许可符合下一阶段目标；几何目标须有相应独立证据 | 停止、缩小场景范围或选择较简单基线，均是有效决策；G0 为 NA 不可自动通过几何目标 |

所有阈值同时查看逐场景结果；平均改善不能掩盖某类场景系统性崩坏。若 seed 波动超过候选增益、轨迹误差主导，或按第 6 节规则缺少任一必要 arm/seed 配对，结论为 **inconclusive**，不能通过只展示最好 seed 消除不确定性。

## 10. 阶段完成条件与报告结构

本阶段以获得可复核结论为完成标准，不以证明设想正确为标准。允许结果为：支持 H2 但不支持 H4；普通深度初始化更好；渲染改善但几何未知；或在既定资源下无法完成有效比较。

最终报告至少包含：

1. 冻结的协议、模型及配置版本、数据和划分哈希、许可状态。
2. 全部计划运行的状态，包括失败、超时、重跑、未执行及原因。
3. 逐场景、逐 seed 的质量与资源表，以及预注册的配对对照；S3/D1 另列 teacher 与实际监督覆盖、跳过样本及持续低覆盖状态。
4. 固定视角的 raw、初始化后及优化后可视化，统一显示尺度；早期与回访留出块均渲染同一个最终场景，明确其离线 batch 性质。
5. 几何证据与自洽性指标分开呈现，明确参考误差和 pose 暴露条件。
6. H1–H4 的支持、未支持或未验证状态；下一步只针对本轮暴露的问题。

**本文件的存在不表示上述检查已通过，也不表示已有代码能够运行全部实验组。** 进入执行阶段前，须由实际实现和运行记录逐项确认。
