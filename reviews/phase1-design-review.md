# 第一阶段研究设计审查

**审查范围：研究问题、实验对照、证据边界与执行前置条件。**

**当前状态：仅完成文档设计；没有运行模型、没有实测质量或性能，也没有据此批准产品接入。** 本审查可随仓库公开，便于复核方案如何避免不可归因的正面结论。

## 1. 核心判断

用 SHARP 作为局部高斯初始化，再用固定相机轨迹和多视图 RGB 形成共享场景，是可以被小规模实验检验的路线。Depth Pro 2 L 的米制先验有可能帮助尺度和表面稳定，但“深度更稳定”“输入是视频”和“最终得到一个 PLY”都不足以证明完整场景几何正确。

第一阶段最有价值的问题是：**相对于普通深度反投影高斯，SHARP 初始化策略提供了多少可重复的实际增益，代价是什么？** 若只比较原始单帧 SHARP 与加入深度、特征、融合和优化的完整系统，无法回答这个问题。S2/D0 和 S3/D1 对比的是整套初始化策略；深度使用量、层数、外观和协方差仍有差别，因此不能解释为某个 SHARP 特征的净因果效应。

## 2. 本设计已落实的控制

| 容易出现的问题 | 协议中的处理 |
|---|---|
| 把独立高斯相加当作完整重建 | 共享世界坐标与共享多视图优化；S0 仅诊断原始冲突 |
| 多个改动同时进入实验组 | S1→S2 只增加每帧单标量尺度初始化；S2→S3 增加深度损失 |
| 缺少合理的简单基线 | D0/D1 使用同一 DP2 版本、预算、融合算子和优化，比较初始化策略的实际价值；不假定深度使用方式相同 |
| 公共模块偷偷使用 DP2，使 S1 被污染 | 各组准入几何来自各自初始化；共享算子不得向 S1 引入 DP2 |
| 以 DP2 自己作为几何真值 | 独立几何参考与内部深度一致性分开报告 |
| 通过降低 alpha 或扩大 mask 获得小深度损失 | 固定 teacher 区域，记录实际监督覆盖；空监督与持续低覆盖按失败/不可评估处理 |
| 无几何参考被误记为失败或成功 | G0 判断几何门槛可评测性；不满足时为 NA，允许完成受限范围的第一阶段 |
| 特征模块与深度干预捆绑 | tracks 只做 source-only 诊断，不进入准入或优化损失 |
| 时间连续帧被当作独立样本 | 三个连续留出块；统计单位是独立场景，seeds 先在场景内汇总 |
| 视频上下文包含 test 图像 | 先划分 view split，再运行 SHARP、DP2、匹配和所有场景更新 |
| 已知轨迹被误称为精确真值 | 记录误差、时间同步与 `pose_provider.used_eval_rgb` |
| 在测试结果上选最优 checkpoint | dev 冻结步数和规则；test 只做隔离评测 |
| 缺失或算法失败后只统计幸存者 | 必要 arm/seed 必须完成 4 场景×3 seeds；不完整时总体 inconclusive，完整子集仅作探索性披露 |
| 为提高均值牺牲视图覆盖 | G1 限制共同 ROI 覆盖下降，早期与回访分组分别展示 |
| 更快的结论来自隐藏缓存或离散保存 | cold、warm、cached replay 分开；等时间包含必需初始化成本，报告 checkpoint 预算使用率和剩余时间 |
| 高斯数相同被当作全部公平性 | 同时报告有效数量、收敛、端到端时间、内存和属性分布 |
| 把离线优化 checkpoint 当在线回访状态 | P1 只比较最终场景对早期/回访留出块的解释能力；batch lookahead 日志不证明无遗忘 |
| 阴性结果被视为任务未完成 | 明确允许“不支持 SHARP 额外价值”作为有效阶段结论 |

## 3. 执行前阻塞项

以下项目没有因文档写完而自动解除。执行者必须给出具体证据。

### B1. 使用许可与数据权利

核对代码、权重和数据各自条款。Depth Pro 2 的公开模型许可排除产品开发，不能把公司内部验证自动等同许可中的非商业科学研究。若本研究目的不在许可范围，需适用授权或重新定义模型方案。见 [官方 LICENSE_MODEL](https://github.com/apple-aiml-research/ml-depth-pro-2/blob/main/LICENSE_MODEL)。

### B2. 数据和标定可用性

尚需确定具体 2 个 dev 与 4 个 test 场景、真实 source/heldout ID、正确 K、固定米制轨迹及同步信息。若只有普通视频而没有可靠轨迹，先完成一个独立、可记账的轨迹获取步骤；不能让不同组各自求解 pose 后仍声称只比较初始化。

应尽量获得独立几何参考。没有合格参考时，G0 为 NA，最终结论收窄为渲染质量、资源及自洽性；这不阻止该范围内的阶段完成。部分场景有参考时可描述该子集，但不把子集结果套入面向全部 4 个场景的几何推进门槛。

### B3. 实现尚需检查

需要实际检查模型预处理、SHARP 输出坐标、深度单位、相机轴向、`s_i` 对中心与协方差的同步缩放、D0/D1 的 footprint 与 opacity、共享优化器及每组数据依赖。当前文档不构成实现通过的证据。

### B4. 资源预算待 dev 实测

P1a 有 8 次基础运行、最多 4 次 S3/D1 诊断，另有最多 8 次新增完整 dev 优化运行用于有限调参；总上限为 20 次计划运行，其中 2 次 S0 不优化。每次候选变更都在 2 个 dev 场景配对运行，最多 4 次变更，按资源、D 臂 footprint/opacity、深度权重、步数的预设顺序进行，记录候选与选择目的。预算内不能冻结不意味着可以转向 test 调参。

P1b 完整矩阵为 60 次优化运行。尚需通过实际硬件测得单次时间与内存，再冻结总预算。模型权重大小不是峰值显存，推理时间也不是完整场景构建时间。仅已证实的基础设施故障允许一次同配置同 seed 重试，失败成本不能隐去；算法 OOM/NaN 或缺失使对应整体假设 inconclusive。

## 4. 高优先级审稿问题

### R1. 深度尺度校准不能暗中变成几何真值注入

S2 只允许每个关键帧一个标量。拟合 mask、稳健估计及回退逻辑必须固定。若改为逐像素移动、强制所有层贴到 DP2 表面，已改变研究问题，须另设实验组。

还应检查 S1/S2 准入集合是否大幅变化。相同算子作用于不同尺度会产生不同候选集合，这是系统效果的一部分，但不能被称为纯坐标缩放的直接作用。

### R2. SHARP 的背层和可见表面需要区分

单张深度只描述当前可见表面。把每个高斯、特别是遮挡后方的预测层，都监督到同一深度，会破坏表示。S3/D1 应监督经过有效性筛选的渲染表面深度，同时公开多层混合的处理。未观测内容不能计作已证实的重建覆盖。

还须检查 depth loss 的“mask 逃逸”：即使 alpha eligibility 的选择已 detach，优化仍可能在后续步骤降低 alpha，使更多像素退出监督。分别维护固定的 `teacher_fixed_mask` 与渲染相关的 `renderer_mask`，记录像素排除原因和每帧实际监督覆盖，预先冻结持续低覆盖的失败规则；空监督不能依靠分母 epsilon 被记成零误差。见 [TECHNICAL_DESIGN.md §10.3](../docs/TECHNICAL_DESIGN.md#103-s3与d1独有的depth-loss)。

### R3. 简单基线必须有合理初始化

D0/D1 的普通高斯需要公开 footprint、旋转、颜色空间和 opacity 规则。固定 degree 0，保持同一优化参数类别。在 dev 做有限调节可以，但不允许对 SHARP 大量调参、对 D0 使用未经检查的默认值。

高斯预算只能从 `{250,000, 500,000, 1,000,000}` 中选择统一档位，在 dev 冻结；不得按 test 场景或组别更换。即便预算相同，两套初始化的深度使用量与表达方式仍不同，应将结论写成策略比较。

### R4. “已知位姿”仍可能暴露留出图像

源于全视频 SfM 或录制时视觉追踪的轨迹，可能已使用 test RGB。必须披露；严格的 reconstruction-only 留出与整条几何链路未见图像是不同结论。禁止在 test 评测阶段重新匹配、对齐或拟合相机来改善分数。

### R5. 重复高斯不能仅通过总数判断

固定预算会掩盖重复区域挤占新区域的问题。须检查同一个最终场景在早期与回访留出块上的质量、准入来源分布、预算排除或代表替换比例，以及预标注单平面的双层贡献。邻近中心和相似颜色都不是同一表面的充分证据。

P1 的 DP2 上下文与跨 source 准入具有 batch lookahead。按 source 时间排序的候选日志仍然可能知道未来；优化 checkpoint 只表示离线求解进展，不能称为回访前后状态，不能证明在线无遗忘。真正的因果回访应在 P2 对每个 source 时间前缀独立重算深度、对应、准入和优化，并单独记账。

### R6. 不宜过早引入可学习的全局特征

S2Tok、GlobalSplat 和 StreamGS 可以指导后续设计，但本轮加入 learned tokens、特征网络微调或可学习融合器，会扩大训练、数据与归因问题。现阶段 tracks 只用于 source-only 诊断，不参与准入或损失；确定性准入使用各组自身的投影、渲染深度和可见性。只有明确发现什么错误不能由当前模型修复，再定义下一阶段干预。

## 5. 结果解释规则

| 观察结果 | 应有的解释 |
|---|---|
| S1 明显优于 S0 | 多视图共享优化重要；尚不能归因于 DP2 |
| S2 优于 S1 | 支持单标量深度尺度初始化；不能推断逐像素深度全部正确 |
| S3 与 D1 都受益 | 支持深度残差机制；不专属于 SHARP |
| S3 与 D1 相当，D1 更便宜 | SHARP 的额外复杂度目前缺乏支持 |
| 渲染更好，但独立几何更差 | 存在外观与几何权衡，不能声称 Real-to-Sim 更可靠 |
| 只在一个场景或最好 seed 受益 | 证据不足，保留逐场景差异与不确定性 |
| 必要 arm/seed 缺失或算法失败 | 对应整体假设 inconclusive；填 NA，不按幸存者重算通过比例 |
| 平均图像指标提高但早期或回访覆盖塌陷 | 报告质量与覆盖权衡；G1 未通过，不把平均改善称为无退化成功 |
| 所有组在同一区域失败 | 优先检查轨迹、曝光、可观测性和输入证据，不直接归咎于融合模型 |
| 按协议得到无增益结果 | 阶段完成，可据此减少后续投入或采用简单基线 |

协议中的 0.01 LPIPS、0.3 dB、3 cm 等是探索性筛选门限，需要在 dev 结合噪声和参考误差冻结。它们不构成统计显著性证明，也不应移作产品验收 SLA。

## 6. 审查结论与下一步

**建议保留这个分阶段设计，并把 B1–B4 作为执行前的明确阻塞项。** 其中预算的解除发生在 P1a 实测后、P1b 启动前；G0 缺失仅限制几何结论，不自动阻塞渲染实验。只有数据、实现、参数和成本可复核，才运行冻结的 P1b。这个顺序允许研究结果不支持 SHARP 初始化策略的实际价值，也允许发现深度有用但共享优化才是主要贡献。

若第一阶段得到清晰、可重复的误差模式，第二阶段只选择一个干预：例如更稳健的表面关联、受限的局部几何修正，或持久场景特征。不要同时加入所有候选机制后重新回到不可归因的比较。
